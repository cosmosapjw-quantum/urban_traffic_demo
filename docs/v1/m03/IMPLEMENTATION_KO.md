# M03 활동 측도와 복수 출입구

`compile_activity(CitySnapshot, block_id, kind, patches)`는 주거 인원, 일자리 기회,
서비스 기회를 서로 다른 측도로 만든다. 주거·일자리 패치 총량은 기존 블록 장부와
일치해야 한다. 서비스 기회는 명시한 `service_stock`과 대조한다. 기본 분포는
균일 면적 prior다. 선언된 점 질량과 단순 polygon의 균일 밀도를 지원하며,
겹치는 패치는 가산 밀도라는 뜻이다. 실측 건물·주민 분포를 추정하지 않는다.
구멍과 건물 solid 입력은 `UNSUPPORTED_GEOMETRY`다. 한 점의 합산 질량이
100 이상이면 대표성 경고를 보존한다.

`activity_access`는 기존 AreaAccess의 삼각형 구적법과 내부 visibility graph를
사용한다. 각 표본은 물리적으로 가장 가까운 문에 배정되고 동률은 균등 분할된다.
문마다 조건부 지연 atom은 256개 이하이며, 조건부 법칙을 사용할 때는 반환된
문 확률을 반드시 활동 총량에 곱한다. 일반화 비용은 물리 시간에 넣을 수 없다.
분포에는 블록 내 이동만 포함되므로 같은 private connector 시간을 다시 더하면 안 된다.

면적 구적법의 평균 오차는 셀 RMS 반지름/속도의 가중합으로 제한한다.
압축의 평균·질량은 보존하고 분산 손실과 평균 절대 압축 오차는 별도로 반환한다.
p95와 분산은 구적 추정량이다. matrix는 depth 1/2의 실제 차이를 기록하며,
이를 분위수의 보증된 오차라고 부르지 않는다. 이동시간은 일정 속도의 평면 geodesic
근사다. 지형 경사는 출입 corridor의 건설 가능성에서 검사하고 보행 속도를 보정하지 않는다.

`compile_entry`는 동일 snapshot의 등록된 블록 경계 node와 실제 접촉하는 문,
블록 내부 corridor, 폭을 포함한 수계/보호구역, 지형 경사와 길이를 검사한다.
용량은 입력한 veh/s 공학 prior다. 공사 길이는 비용이며 접근시간에 중복 가산하지 않는다.
기존 문은 공사비 0으로 유지된다.

`select_entries`는 최대 12개 후보의 유한 부분집합을 비교한다. 목적함수는
활동가중 평균시간 + 길이 가중 비용 + 문 확률로 가중한 이용률 제곱 비용이다.
활동 측도와 별도로 입력한 차량 전망량, horizon 초, veh/s로 부하를 계산한다.
거리 상한은 구적 셀 전체를 포함하는 보수적 반지름으로 검사한다. 실패한 셀의
활동량은 미서비스 상한으로, horizon 내 용량 초과는 차량량으로 각각 남긴다.
사람을 차량으로 암묵 변환하거나 탈락한 질량을 재정규화하지 않는다. 동률 후보는
모두 반환하며 ID로 물리 우선권을 정하지 않는다. 연속 공간의 전역 최적 건설망을
찾았다는 주장은 하지 않는다.

`intrazonal_law`는 같은 블록의 두 활동 측도의 독립 결합을 내부 geodesic 지연으로
보낸다. 같은 블록이라는 이유로 0초 완료를 만들지 않는다. 실제 일치점은 0 거리일 수 있다.
이는 D01의 수요 endpoint용 법칙이며 동적 수송 엔진은 아니다.

검증 matrix는 L자 오목 블록의 1/2/4배 공간 규모를 사용한다. 800:200 활동과
단일/복수 문, 4분할 총량, 내부 이동, 면적 구적 refinement를 비교한다.
8km 도시 18개의 M02 지도 검증이나 V02의 전도시 접근 감사와 별도인 M03 fixture다.
동적 문 대기열·도로 receiving과의 공동 수용은 후속 T03에서 PacketNetwork에 연결한다.
24시간 10만 주민 실행, 실제 도시 보정, 최종 V1 수용은 이 결과로 주장하지 않는다.
