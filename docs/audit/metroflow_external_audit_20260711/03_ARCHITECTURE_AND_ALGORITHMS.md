# Current Architecture And Algorithms

## 1. System Boundary

Metroflow is a Python package with three execution layers:

1. **Python orchestration and frontend surfaces**: configuration, simulation
   state replacement, events, replay, benchmark runners, diagnostics, static
   map rendering, and experiment control.
2. **NumPy authoritative numeric state**: road CSR arrays, link/node flow,
   active-agent slots, routing costs, labels, and graph tensors.
3. **Optional accelerators**: a PyO3 Rust extension for CPU kernels and lazy
   JAX/Optax experiments for dense flow and graph-surrogate probes.

The base install requires only NumPy. JAX, Optax, Torch, and maturin are extras.
Explicit optional backend selection is intended to fail closed; only `auto`
may fall back to the baseline.

## 2. Package Map

| Package | Responsibility | Authority / caveat |
|---|---|---|
| `core` | legacy frozen tuple `WorldState`, contracts | compatibility runtime |
| `city` | topology, morphology, connectivity, zoning, POIs | synthetic only |
| `map` | typed centerlines/sections/nodes, OSM adapter | OSM offline reference |
| `demand` | citizens, schedules, trips, accessibility | deterministic generation |
| `flow` | link/node arrays and point-queue turn flow | NumPy authority |
| `routing` | dynamic potential, policies, scoring | baseline route legality |
| `sim` | new runtime state/init/step/agents/events/replay | incomplete self-drive loop |
| `traffic` | legacy mesoscopic edge and routing compatibility | parallel semantics |
| `landuse` | lagged accessibility response | wired only to legacy spine |
| `learning` | EMA/UCB/blending, labels, surrogate experiments | disabled by default |
| `metrics` | measured benchmarks and summaries | diagnostic unless stated |
| `benchmarks` | atlas, GPU/NN probes, artifact renderers | experiment surface |
| `ui` | static map, runtime snapshot, HTML/PNG diagnostics | smoke/review only |
| `backends` | lazy Rust/JAX wrappers | copy boundaries explicit |

The highest cross-package fanout is in `sim`, followed by `metrics` and
`benchmarks`. Notable dependency problems are `sim` importing `ui` snapshots
and buffers, city/map mutual relationships, and two parallel routing/traffic
surfaces. Local imports avoid some import-time cycles but do not remove the
conceptual cycles.

## 3. Authoritative Runtime Step

`sim.step.simulation_step` currently performs:

1. apply control command and advance clock;
2. activate/deactivate events;
3. transform event capacity/speed effects into link state;
4. activate existing pending trip requests;
5. run node/link flow update;
6. refresh/reuse OD route candidates;
7. allocate, reroute, move, wait, complete, or release active agents;
8. check invariants;
9. build a UI snapshot;
10. accumulate metrics and nested timing counters.

All changes are applied through replacement helpers by convention. However,
`SimulationState`, static/dynamic refs, dictionaries, and NumPy arrays are
writable; the “immutable state” rule is not enforced by the Python type system.

### Functional Gap

The flow step consumes `NodeState.turn_demand`, but no production runtime stage
derives this array from active routes. Initialization creates zeros and the flow
engine carries demand forward. Eager activation seeds source link queues, but
turn demand, turn flow, and outflow stay zero. Newly allocated agents therefore
cannot consume movement budgets generated by the same model.

The default initializer also uses `eager_trip_generation=False`, and no
ongoing trip-generation stage is in `simulation_step`. A default runtime can
therefore remain empty. These are product-closure defects, not performance
issues.

## 4. Legacy Multirate Runtime

`sim.orchestrator.step_world` operates on frozen tuple-based `WorldState`. It
contains fast traffic evolution plus medium accessibility and slow land-use
cadences. It is better aligned with the original LUTI concept, but it does not
own the new active-agent pool, flow arrays, candidate cache, or runtime replay
surface. The two spines are compatibility layers, not a single composed model.

## 5. Flow Algorithms

### NumPy Node/Link Flow

`flow.engine` normalizes float32 arrays and computes:

- priority-weighted turn demand;
- per-source and per-destination segment sums using `np.add.at`;
- upstream queue/capacity sending supply;
- downstream receiving supply;
- feasible turn flow as the minimum of demand and allocated supply, with
  forbidden turns forced to zero;
- link inflow/outflow and queue replacement;
- capacity-violation flags;
- linear queue-delay cost of the form `base * (1 + queue / capacity)`.

This is a deterministic point-queue/node allocation baseline. It is not a
calibrated cell-transmission, link-transmission, kinematic-wave, lane-changing,
or signal-control model. The signal timer is state metadata, not evidence of a
complete traffic-signal controller.

### Legacy Edge Evolution

`traffic.meso` uses stock and queue conservation. Feasible outflow is bounded
by request, available mass, and capacity; travel time is free-flow time plus a
queue/capacity term. It has baseline, Rust, JAX, and auto dispatch, but remains
a compatibility path separate from `flow.engine`.

## 6. Routing Algorithms

### Dynamic Potential

The authoritative algorithm is reverse Dijkstra over incoming-link CSR. It
starts at a destination, ignores blocked/zero-capacity links, and computes
float32 node cost-to-go. The heap-staleness comparison was explicitly fixed so
valid float32 improvements are not discarded.

### Candidate Construction And Choice

Legal next links are scored by link travel-time cost plus destination potential.
The baseline builds a deterministic greedy route or ranked K candidates with
turn restrictions, hop limits, and tie-breaking. Each candidate records:

- ordered link IDs;
- summed generalized cost;
- path-size factor measuring overlap;
- utility `-cost + gamma * log(path_size)` when gamma is positive.

The default K is one and gamma is zero, preserving least-cost deterministic
selection. Candidate caches include network/state generation, destination,
event/incident generation, and refresh policy. Conservative rerouting occurs on
incident or cadence boundaries with cooldown and baseline fallback.

Rust can compute potentials, greedy/ranked paths, metadata, scores, selection,
and reroute actions, but Python remains the legality and state authority.

## 7. Active-Agent Algorithm

`ActiveAgentPool` stores packed NumPy slot arrays. Activation selects a route,
assigns the first link, records candidate metadata, and inserts one vehicle into
the source queue. Movement is deterministic by slot ID and consumes integer
budgets derived from previous link outflow. Final-link completion consumes a
sink budget based on effective capacity. Zero sink capacity records a wait;
missing routes release slots as failures.

The Rust agent backend returns an action plan only. Python applies immutable-
replacement-style pool updates. This boundary is appropriately conservative,
but the planner cannot compensate for the missing flow-demand coupling.

## 8. City Generation Pipeline

The synthetic generator resolves a morphology style and seed, then combines:

1. terrain/morphology fields and style anchors;
2. arterial/backbone corridors;
3. district cells and local meshes;
4. style-specific local fabric and continuous infill;
5. weak-connectivity repair with explicit collector stitches;
6. optional planar intersection splitting;
7. typed centerline and road-section compilation;
8. node-interface compilation;
9. structural morphology gates;
10. legacy or morphology-gated zones and POIs.

Styles include ring/radial, grid, polycentric, river-corridor, mixed/superblock,
and organic variants. Metrics cover orientation/grain, circuity, density,
intersection mix, continuity, cell presence, and local-junction proximity.

The generator’s implementation is not proportionate to this conceptual list.
`city/generator_v2.py` is 5,654 lines and `_build_preview_topology` is roughly
4,338 lines. `district_mesh.py` contains many tactical style-bias functions.
The code is difficult to audit for interaction effects, and passing morphology
gates can reward metric-specific construction rather than general realism.

## 9. Demand, Accessibility, And Land Use

Demand builders deterministically create citizens, schedules, and trip
requests from synthetic zones/POIs. Accessibility maps zones/households/jobs to
network reachability. Land-use evolution consumes lagged accessibility in the
legacy scheduler. Morphology-gated zone/POI placement preserves IDs, counts,
types, capacities, and fingerprints.

What does not exist is equally important: no observed OD calibration, no
household travel survey, no ongoing integrated trip-generation cadence, no
parcel/building market, and no closed `SimulationState` LUTI loop.

## 10. Learning And GPU Surfaces

The runtime contains deterministic EMA/UCB and policy-blend utilities, disabled
by default. Simulator label exporters preserve Dijkstra authority. The optional
surrogate surface does not currently establish a trained production neural
network; its baseline is a simple NumPy rank-mean predictor and its Torch path
is experimental.

JAX kernels are lazy and optional. The dense-flow experiment keeps arrays on
device for a frozen 512-step chunk. The graph experiment uses directed tensors,
blocked masks, destination context, and a fixed model/control comparison. No
JAX result owns route legality or state mutation.

## 11. Replay, Metrics, And UI

Replay boundaries fingerprint config, backend choices, geometry/zoning, route
cache state, and deterministic arrays. Benchmark suites report parent and
nested stage timings, call counts, cache behavior, and backend metadata.

Static maps, morphology atlases, runtime diagnostics, and HTML reports are
valuable inspection tools. They do not establish empirical validity. The UI is
best described as a diagnostic frontend, not a complete interactive simulator
application.

## 12. Data Ownership Summary

| Data | Owner | Mutation model |
|---|---|---|
| Config and orchestration | Python | dataclass replacement/convention |
| Road/link/node/agent arrays | NumPy | writable arrays, replacement intended |
| Rust kernel inputs/outputs | Python wrapper | list/`Vec` copies |
| JAX experiment tensors | experiment module | device arrays, no runtime authority |
| Replay fingerprints | Python | deterministic serialization |
| Reports/UI | Python | derived diagnostic views |

The target architecture is coherent, but the enforcement is weaker than the
documentation: state immutability is conventional, layers are cyclic in places,
and the two runtime authorities remain unresolved.
