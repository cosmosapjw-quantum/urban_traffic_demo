## Stage 3 · R3 lifetime theorem / C3 formula
**Lemma (source-shared immutable event payload; derived):** Suppose a snapshot owns `Arc<Vec<EventRow>>` A and its committed road/service owner holds `Arc::clone(&A)` while neither mutates A. Then `Arc::ptr_eq` is true, the underlying Vec element allocation is physically one allocation independent of the count of Arc owners, and the legacy element/order/bit payload remains unchanged. At a physical service commit the new `Arc::new(events)` creates new backing only; the retained input snapshot continues owning the original backing. This does not claim different Arc backings with equal value share memory. Proof: Arc cloning increments refcount without cloning T; immutable backing is not mutated; replacing the owner's Arc does not affect the source or its strong references. Each read of the ordered EventRow slice yields the original tuple. Serialization iterates unchanged EventRows and writes the original fields individually.

Define I and C as *actual old input and committed EventRow Vec capacities* times `sizeof(EventRow)`; G as the existing conservative candidate event-growth term `3 max(generated,4) sizeof(EventRow)+96`. Original service event structural charge `I+C+G` is correct before sharing. After converting to immutable Arc and maintaining the input Arc for the duration of the call, a pointer-identity-backed charge `I+C-δ min(I,C)+G`, where `δ=1` if and only if `Arc::ptr_eq(input,current)`, is an upper bound for distinct old Vec *payload* capacity (and unchanged candidate growth) because equal Arc implies identical Vec allocation and capacity. For unequal Arc, δ=0, retaining the original conservative accounting. The separate process 8GiB address-space/RSS guard still covers Arc control blocks, allocator metadata, unrelated snapshots and other owners; the revised formula is **not** a bound on total process memory. The native overall byte policy is not increased.

This is a scientifically relevant change only when old input/current snapshots were duplicated or newly share backing, and a physical source-bound guard confirms changed source code actually improves a blocked phase. Source-id accounting never admits value equality as pointer identity. Source code must recompute δ **for every physical tick**, because after committing new events input/current may diverge; treating a one-time alias as permanent would undercount later work. Preserve unchanged `source_event`, `road_work`, `engine_admission`, `service_sinks` and `journey_commit` final safety/physical validation boundaries for independent tests.
