## S02: exact block rank representation
Read prior trace: 67,269,906 physical road rows, 1,187,008 packets; 18,666,739 incoming refs at rejection. The existing 12B tuple is (event index, path offset, control index). Event backing owns tag/mass/birth; no need to duplicate f64. For block B=128, let integer column base a=min and width w=ceil(log2(max-min+1)), including w=0 for constant columns. Row rank i decodes a+bits(i*w,w); no change of order or floating arithmetic. Three independently packed columns, two 64bit header words, exactly 16+16*(w_event+w_offset+w_control) bytes/full block; raw 1536B fallback when not smaller. O(1) rank access, fixed 128-ref reusable tail; allocate once per full block (not per event). For any block, byte count <=1536, no compression assumption needed for correctness. A conservative preflight must charge new raw block and its independent staging tail plus both descriptor allocations; credit only sealed packed blocks, never prospective compression. Prior partial row traces (6,427,966 same-rate contiguous rows) motivate block locality but do not prove the achievable ratio. Sources: Lemire/Boytsov, DOI 10.1002/spe.2203 (binary packing), public https://github.com/lemire/FrameOfReference and https://github.com/fast-pack/simdcomp (README retrieved; no code copied, no license compatibility or measured performance transfer asserted). Original implementation in Rust. Exact rank access tested across widths 0..32, signed-domain irrelevant for integer indexes, constant and wide fallback, multiple block growths. This is lossless transient representation, not a new physical approximation.
