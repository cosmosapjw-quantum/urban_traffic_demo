### Proposition: conservative blocked-transfer closure (derived)

For each directed link e, stock X_e=A_e-D_e in vehicles, capacity K_e>0 (veh) and server c_e>0 (veh/s). A batch of mass m>0 follows a finite legal path. At its admission time t, passage eligibility u=t+tau_e is finite and positive; an ordered server finishes at max(u,F_e)+m/c_e, staged to the road clock h. If the next link f has available storage K_f-X_f<m, retain the whole head in e, with no fictitious exit or downstream entrance. At a feasible transfer, atomically change (X_e,X_f) to (X_e-m,X_f+m). Source and sink transitions change a single stock and the external ledger. Use FIFO at each link and deterministic request ordering; completed blocked service releases the server only when the head can move. Each batch is prechecked against every path's K (or must be split explicitly). Cyclic gridlock is retained as unfinished stock, not deleted.

Induction: initially all stocks vanish. Source admission iff X_e+m<=K_e, and internal transfer iff m<=X_e and X_f+m<=K_f; then each changed stock remains in [0,K]. The sum of internal stock changes is zero. Hence total admitted minus total exited equals sum_e X_e at all events. Include waiting origin and door queues to prove total released minus completed equals all active mass. The head cannot be bypassed by another batch in the same link: admission and removal append/pop a FIFO, and only the head can request service. A finite event schedule is deterministic for fixed tie keys. Unlike the original point queue, a downstream saturated link can hold upstream mass, cause upstream saturation, and block origin admissions. The model approximates within-link spatial location and uses batch-level whole admission; local FIFO is not network-wide FIFO. Service rates, time increments and storage have different dimensions. In the infinite-storage limit the blocking mechanism disappears, though the chosen FIFO server timing and tie policy must be matched separately before claiming numerical parity. This constructive model is a separate candidate for testing original explanatory traffic signals, not a replacement accepted by V03.

## S02. Exact class moment streaming

For each class k, the existing receiving update stores an ordered sequence (m_i,l_i) from survivor rows followed by received rows. It computes l'_k=fsum(m_i*l_i)/fsum(m_i). The two expansion states can instead be advanced independently in that same order. Induction on the row index identifies each partial-expansion vector with its original fsum loop; final rounding and division are unchanged, including multiplication before summation. No rearrangement or algebraic replacement of the IEEE arithmetic is used. The raw class vector allocation and its possible doubling overlap disappear. For N local rows the removed minimum payload is 16N bytes (not an estimate of peak RSS). Expansion storage depends on binary exponent range, not on storing every row. This preserves original latent-response physics, unlike averaging classes.

Implementation: RoadExpansion and ClassMoments in v1_road.rs. Independent copy of the pre-change summation is compared with the streaming wrapper on 192 deterministic finite sequences, plus a marked-moment test. Focused Rust test passed.
