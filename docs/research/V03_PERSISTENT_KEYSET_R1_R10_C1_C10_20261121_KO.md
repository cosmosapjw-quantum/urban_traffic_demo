## R3/C3 · Conditional source-key sharing theorem and memory crossover

For every original *uniform* packet (P_j) with `CorePart` rows of length `r_j`, define its ordered key sequence (K_j=((tag_{ji},offset_{ji}))_{i=1}^{r_j}) and its exact physical payload sequence (V_j=((mass_{ji},birth_{ji}))_{i=1}^{r_j}). Original physical iterator also appends the packet endpoint header `(a_j,b_j)` bit-patterns to each row. Define the proposed *conditional* representation (S_j=(a_j,b_j,shared(K_j),private(V_j))). Equality for reuse is **same length AND elementwise equal ordered key values**. An initial fingerprint/hash may index candidates but cannot establish equivalence; full exact comparison must decide. There is no condition that masses, birth values or endpoint headers match across different packets, and they must never be aggregated or shared by value.

**Lemma (derived):** For every `j,i`, reconstruction from `(K_j,V_j,a_j,b_j)` yields the exact original `CorePart(tag,offset,mass,birth)` bits and the same `Part` value in source position `i`. The derivation is a projection/inverse of the tuple, with no arithmetic. Therefore any original function iterating source rows, including the ordered binary64 `sum`, packet FIFO and `write_state`, receives the same ordered tuples; implementation may share only immutable `K_j` and must not reorder or combine physical cohorts. This proof relies on no change to `CorePart` u32 representability, and `Mixed` packets remain the exact original wide-index/heterogeneous fallback. Keyset equivalence is *not* full physical state equivalence.

Let `R=Σ_j r_j` be the total uniform CorePart row count, group packets by exactly equal `K_j`, and `U=Σ_groups len(K_g)`. On the pinned host `CorePart=24B`, two u32 keys=8B, and two f64 payloads=16B. Original **row payload only** `M_old=24R`, separated shared-key representation `M_key=16R+8U`, so potential row-payload saving is **`ΔM=8(R−U)` bytes**. This is *not* the net allocation saving: two Arc allocations, keyset dictionary, packet enum size and transient construction can offset it. For a group of `m` packets each of `r` rows, `ΔM=8r(m−1)`; e.g. m=2,r=2 saves only 16B and should **not** be interned given metadata cost. A gate on actual measured repeated `R−U`, per group length and extra payload/header lifetime is mandatory before enabling a production codec. Hash collisions must be resolved with exact element comparison. No claim of source-wide repetition or >25,745B saving is made before the original 25,680 checkpoint census.

A competing exact source format encodes `(tag,offset)` in one u32 via a checked injective pair map if route lengths and tag upper bounds permit, storing the key sequence in 4B/row instead of 8. That is a different *conditional* representation and would save `4R` additional row bytes only in separate key arrays; keeping two f64 values inline in `CorePart` cannot necessarily shrink the aligned Rust struct from 24B to 20B because 8-byte alignment may pad it. This option is held until actual native route/index bounds and keyset statistics are measured.
