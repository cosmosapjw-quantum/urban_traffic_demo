## Stage 2: R2 original-science context / C2 source-to-wire mapping

Read actual current `crates/metroflow-rust/src/v1_road.rs`: `CorePart` (lines near 140) has exactly four fields, two `usize` index components and two `f64` moment components. `PacketParts::Uniform` owns one `Arc<Vec<CorePart>>` plus exact common endpoint pair; `PartIter` expands each row to a full `Part` (`usize,usize,f64,f64,PackedTime,PackedTime`). `PacketParts::pack` constructs compact rows only when both endpoint bit patterns coincide; `Mixed(Arc<Vec<Part>>)` is a supported full-width representation for heterogeneous endpoints. `V1Road::write_state` writes every Part's tag and offset as `write_len` (u64 wire), mass/birth as original `f64`, and endpoint presence/values unchanged. `read_state` reads `Part` then packs, so the *in-memory* CorePart index widths are not checkpoint ABI. `CorePart` is used in the existing direct uniform nonpoint/point paths and in shared-Arc accounting; the latter computes byte envelopes from `size_of::<CorePart>()`, so a smaller real allocation naturally reduces retained backing budgets rather than subtracting an assumed credit. The Python ABI test `tests/v1/test_native_packed_intervals.py::test_actual_part_layout_and_byte_derived_record_ceiling` currently asserts 32-byte CorePart, 48-byte Part, 64-byte EventRow and 32-byte Packet on the pinned host, so it must be updated to assert the measured *new* source layout and verified against the freshly built extension.

Primary traffic-science boundary: Bar-Gera & Carey, *Representation requirements for perfect first-in-first-out verification in continuous flow dynamic models*, Transportation Research Part B (2017), https://scispace.com/papers/representation-requirements-for-perfect-first-in-first-out-4zrcgrs1c8, analyzes representation requirements for network-wide FIFO. Carey et al., *Implementing first-in-first-out in the cell transmission model for networks*, https://eprints.whiterose.ac.uk/id/eprint/82755/3/balijepalli.pdf, describes route/cohort ordering and situations where a local FIFO rule does not ensure route-wide FIFO. These published works justify checking exact route order, but do **not** prove this source-specific Rust byte compression. Here the proof is a direct injective re-encoding of integer labels under a checked range; no number of distinct Part histories is deleted. Partial FIFO and coarse flow/kinetic models remain physically different, separately versioned alternatives.

## Stage 3: R3 constructive injectivity lemma / C3 computational form

**Conditional exact encoding theorem (derived):** Given original `tag,offset: usize` in the representable set `0 <= tag,offset <= 2^32-1`, define `C(tag,offset,mass,birth) = (u32(tag),u32(offset),mass,birth)` and `D(t,o,m,b)=(usize(t),usize(o),m,b)`. Then `D(C(x))=x` *bit for bit* for both integers and f64 mass/birth, because checked integer narrowing is exact in the range and the real values are copied unchanged. Uniform endpoint headers are unchanged, so the full reconstructed Part `(tag,offset,mass,birth,a,b)` equals the original exact bit patterns. Iteration order is the original Arc Vec order, hence every f64 sum and FIFO service order consumes exactly the same source sequence. For an out-of-range `usize` input, **do not apply C**: retain the full-width `Mixed(Arc<Vec<Part>>)` fallback with the original tag/offset and exact endpoint bits. Conditional compression does not merge two physical trajectories, histories or source segments.

On pinned x86_64 Rust layout: `CorePart=(usize,usize,f64,f64)` occupies 32B; `CompactCorePart=(u32,u32,f64,f64)` occupies 24B, retaining identical binary64 alignment. Thus one physically allocated uniform backing array of r rows saves exactly `8r` bytes of payload, **25%** of that array. Wolfram exact evaluation confirmed 32→24 bytes, relative 1/4 and the 1,938,545-byte previous blocker deficit corresponds to 242,319 distinct eligible row slots if no other terms changed. This threshold is not a predicted full tick outcome because old retained buffers, source decode, and work phase allowances may all change. Fallback allocation for out-of-range original `usize` means global theorem extends to the full previously accepted physical value domain without truncation; packet-storage *representation diagnostics* for an impossible-for-V03 2^32 route tag may differ from old uniform classification.

Under original V03's 8GiB process address-space ceiling, an actual `Vec<(usize,usize)>` with >= 2^32 distinct route index entries would already require >= 64 GiB for inline entries on this ABI; similarly a path with offset index >= 2^32 needs >=32 GiB of `Vec<usize>`. These bounds make the overflow path inapplicable to physically realized V03 states. This is a resource-bound observation for the original capped release, not a mathematical universal index theorem or a claim about uncapped legacy input.
