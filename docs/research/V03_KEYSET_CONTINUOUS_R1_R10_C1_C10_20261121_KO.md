## R3/C3: exact page-map theorem and postroad continuous keyset construction

**Theorem A (derived, all finite admitted source rows):** For each road destination cell (j), original append-order Part sequence ((p_{j,i})_{i<r_j}) and exactly aligned Mark sequence ((m_{j,i})_{i<r_j}), the fixed page map ((j,i)\mapsto(j,\lfloor i/B\rfloor,i\bmod B)) is invertible and preserves the order of every pair ((p_{j,i},m_{j,i})), even at page boundaries and with signed-zero endpoint/birth fields. Nothing changes in the original source-index combine order, FIFO packet head priority or exact argument sequence of the existing f64 `sum` and weighted sums. This is independent of B>0 and requires only that both Part and Mark use the **same B** and exactly filled preceding pages. Neither source physical equation nor checkpoint wire format changes.

For `R` cumulative source rows charged by the road phase and `G` cell buffers, Part row sizeof 48B, Mark sizeof 16B and Vec header 24B on the pinned 64-bit host, an implementable conservative page capacity envelope is
`M_B(R,G)=64[R+(B-1)G]+96[ceil(R/B)+G]` bytes (R>0, otherwise zero). It counts real Part+Mark pages' terminal slack and the two families of temporarily doubled outer Vec page descriptors, not process RSS. For the actual prior guard sample `R=11,764,502,G=1,586`, source B=64 gives **777,121,952B** and proposed B=128 gives **774,794,848B**; reduction **2,327,104B**, with the *same original guard limit and all other terms fixed*. Smooth approximation (dM/dB\approx64G-96R/B^2) has optimum (B_*\approx\sqrt{(3/2)(R/G)}\approx105.5); integer choice B=96 is numerically slightly lower but non-power-of-two, and B=128 retains efficient exact bit/power-of-two index mapping and fewer page allocs. This is a source-bound performance trade-off, not a theorem of optimal B for every future state.

**Theorem B (source continuation):** Once `step_state` returns a new, still locally owned candidate and its event pages, the road-only incoming, Mark, queue and interval temporary buffers are *out of scope*. A candidate `RoadState` may be interned using exactly the existing full ordered keylist equality comparator, preserving all per-packet mass/birth and endpoint bits. Importantly the interning transient has a real peak: when previous `CorePart` and new canonical key/moment payloads coexist, at most (24R_c+K P_c) bytes of new packet payload/control/index buffers are allocated for candidate row count (R_c) and packet owners (P_c); choose conservative (K=512B/packet) for the bounded HashMap, Vec descriptors and extra Arc/control metadata on the pinned host (a scoped **estimate**, not a universal stdlib allocator bound). Do not use this term as a fictitious credit. Place the transformation **after final contiguous EventRow materialization**, when paged EventRow backing has been dropped, and guard the concurrent old/current/candidate RoadState owners, committed service events, actual flat EventRows, and interning temporary buffer. Then call `intern_exact_keysets` and return the unchanged ordered event vector. This cannot help a *first-step transfer guard before road completion*, hence the independent Part/Mark page mechanism A is necessary.

The actual targeted validation is two separate source gates: (i) old 25,690→25,700 10s candidate transfer guard that failed by 10,161B, and (ii) the multi-step continuous source since 25,700, which must include postroad interning **without a disk save/reload**.
